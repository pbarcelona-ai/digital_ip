Reconstruct.

The top-level FSM separates input capture from corrected output. A full frame lives in the four-read-port buffer while the output raster asks the coordinate pipeline where to sample next.

Integrated data path

01 / BLOCKS

01 / Input capture

axis_in_ctrl accepts AXI4-Stream video, checks line framing, and writes pixels into frame_buffer. The whole image must be present before output starts.

02 / Coordinate engine

coord_gen converts output raster coordinates to fractional source coordinates. Radial/tangential correction is a fixed-latency pipeline; fisheye, panoramic, and perspective use a per-pixel divider and assert busy while it runs.

03 / Sampling & output

axis_out_ctrl clamps sample taps to the image edge, selects bilinear or bicubic interpolation, then emits output tlast and tuser from its tag pipeline.

Top-level control

02 / SEQUENCING
  1. T_LOAD: accept a frame while configuration reciprocal calculations are idle.
  2. When frame_done_in pulses, wait for external-buffer writes to drain if selected, then issue start_output.
  3. Hold the core busy until frame_out_done, then return to T_LOAD.

Frame-rate constraint. The single full-frame store means capture and output do not overlap. Sustained back-to-back frame-rate operation requires a ping-pong buffer extension.

External SDRAM backend

04 / STORAGE

Set vision_system #(.USE_EXT_FB(1'b1)) to replace the default BRAM store with ext_frame_buffer. The top exposes raw single-data-rate SDRAM command, address, bank, mask, clock, and bidirectional data pins. It initializes the device, buffers writes, and refreshes periodically.

Throughput and board timing. The SDRAM path serializes four bilinear tap reads (or sixteen bicubic taps), and backpressures input when its write queue is full. Defaults target 64-bit DQ, CAS 2, and the project’s nominal 100 MHz clock, but this is not a board-qualified PHY: forwarded sdram_clk equals the core clock. Match timing parameters and clock phase to the exact SDRAM and FPGA board before hardware use.

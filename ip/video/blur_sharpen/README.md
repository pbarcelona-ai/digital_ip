# blur_sharpen

Blur and sharpen filter pair for AXI4-Stream video with an AXI4-Lite register map (version: the VERSION register). Two conv2d_core stages are always in line; MODE decides which kernel each stage runs, and a stage that is not needed runs the identity kernel (pass-through), so the latency and throughput are the same in every mode: MODE stage 1 stage 2 result 0 blur identity blurring only 1 sharpen identity sharpening only 2 sharpen blur sharpening, then blurring 3 blur sharpen blurring, then sharpening 4 identity identity pass-through (5-7 also) The blur and sharpen kernels are programmable (reset: binomial blur and unsharp mask, see conv2d_pkg). MODE, FRAME_SIZE, the kernels and shifts are copied when a start-of-frame pixel enters, so a change applies from the next frame and never splits one; stage 2 takes the copy belonging to the frame it is filtering. Registers on the cfg_* / sts_* ports; blur_sharpen_top.sv is the block with its AXI4-Lite register map (src/include/blur_sharpen_regs.sv, ADDR_W = 9): ID "BLSH" / VERSION / DATE at 0x000-0x008, MODE 0x014, FRAME_SIZE 0x018, BLUR_SHIFT 0x01C, SHARP_SHIFT 0x020, STATUS 0x024, INFO 0x028, BLUR_K[i] 0x050 + 4 i, SHARP_K[i] 0x0D0 + 4 i. Each stage: out = clamp((sum(K*p) + round) >>> SHIFT, 0, 2^CW-1). Frames match FRAME_SIZE and have at least 14 pixels (each side >= R + 1): copy A is replaced when the next frame enters stage 1, and up to 13 beats can be between stage 1's scan and stage 2 (isp_window 5, MAC 4, output FIFO 4), so a smaller frame could reach stage 2 after the next one took over A. A and B load the register values while rst_n is low. Golden model: model/blur_sharpen_model.py (frame exact, tb/python). Data - C components of CW bits, tuser = SOF, tlast = EOL. Clock - clk. Reset - synchronous rst_n (active low). Latency - 2 x conv2d_core. Resources - 2 x N*N*C multipliers, 2 x (N-1) line buffers.

blur_sharpen is an IP of the FPGA Cores 4 U digital IP library.
